# Weather → Heltec Mesh Bridge

[🇬🇧 English](README.md) · 🇷🇺 Русский

Бот для Raspberry Pi, который по расписанию рассылает сводки погоды в Meshtastic mesh-сеть через Heltec Mesh Node V4. С удобным веб-UI.

- источник погоды — **Open-Meteo** (без API-ключа)
- связь с Heltec — **USB-кабель** или **WiFi (TCP)** через официальную Python-библиотеку `meshtastic`
- веб-UI на Flask с двумя вкладками: «Настройки» и «Чат»
- чат показывает входящие сообщения mesh-сети (подписка через `pypubsub`), поддерживает ответы, реакции и показывает количество прыжков, RSSI и SNR для каждого пакета
- расписание — **APScheduler** с cron-триггерами, любое количество слотов с собственным набором полей, днями недели и часовым поясом
- длинные сообщения автоматически режутся на чанки `(1/N)` с настраиваемой паузой между ними
- автозапуск через **systemd** одной командой
- HTTPS «из коробки» с автогенерируемым самоподписанным сертификатом (чтобы браузерные уведомления работали даже в локальной сети)

## Что внутри сообщения

Поля выбираются независимо для каждого слота:

- температура + состояние неба
- температура по ощущению
- влажность
- давление (мм рт.ст.)
- ветер (м/с + направление + порывы)
- осадки
- прогноз на сегодня (мин/макс + вероятность дождя)
- завтра: утро (09:00) и вечер (21:00) в часовом поясе локации

Смайлики — отдельный тумблер. Так же есть тумблер «Заголовок» (`Погода — Город`). Пример без смайликов:

```
Погода — Москва
+3.4°C, переменная облачность
Ощущается как +0.8°C
влажность 78% · давление 750.2 мм рт.ст.
ветер 4.2 м/с З (порывы 8)
сегодня -1…+5°C · небольшой дождь · вероятность осадков 60%
Завтра · +5…+14°C · в основном ясно
утро +7°C переменная облачность 10% · вечер +11°C в основном ясно
```

## Что нужно

- Raspberry Pi 4 (или любая Linux-машина с Python 3.10+)
- Heltec Mesh Node V4 (или совместимая Heltec-плата) с прошивкой Meshtastic
- WiFi-роутер или USB-кабель, чтобы соединить их

## Установка на Raspberry Pi

> При первом запуске бот сам создаст `config.json` из дефолтов. Если хочешь заведомо чистый конфиг — скопируй пример:
> ```bash
> cp config.example.json config.json
> ```
> Дальше всё настраивается через веб-UI и сохраняется в `config.json`.

1. Прошей Heltec V4 фирмварём Meshtastic ([гайд](https://meshtastic.org/docs/getting-started/flashing-firmware/heltec/)) и подключи к Pi по USB (или потом настрой WiFi).
2. Скопируй папку проекта на Pi (например в `/home/pi/weather-mesh-bridge`).
3. Запусти установщик:
   ```bash
   cd /home/pi/weather-mesh-bridge
   bash install.sh
   ```
   Он создаст venv, поставит зависимости и добавит пользователя в группу `dialout` (нужно перелогиниться или перезагрузиться).
4. Проверь, что устройство видно:
   ```bash
   ls /dev/ttyUSB* /dev/ttyACM*
   ```
   Должно появиться что-то вроде `/dev/ttyUSB0`.
5. Запусти руками для теста:
   ```bash
   source .venv/bin/activate
   python app.py
   ```
6. Открой `https://<ip-pi>:5000` с любого устройства в той же сети.
   При первом запуске бот сгенерирует самоподписанный сертификат, и браузер
   ругнётся «Подключение не защищено» — нажми **«Дополнительно → Перейти на сайт»**
   один раз, дальше он запомнит. Чтобы отключить HTTPS и работать по простому HTTP,
   запусти с `WMB_HTTPS=0 python app.py` (или поправь systemd-юнит).

## Автозапуск (systemd)

```bash
sudo cp weather-mesh-bridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now weather-mesh-bridge
sudo journalctl -u weather-mesh-bridge -f   # смотреть логи
```

Если у тебя другое имя пользователя или путь — поправь `weather-mesh-bridge.service`.

## Использование UI

### Вкладка «Настройки»

1. **Город** — введи название на любом языке, выбери из списка. Координаты и таймзона подставятся.
2. **Стиль сообщения** — переключатели смайликов и заголовка `Погода — Город`.
3. **Heltec V4** — выбери тип подключения:
   - **USB-кабель** — `auto` находит устройство сам.
   - **WiFi (TCP)** — IP плати и порт (по умолчанию 4403). Чтобы подключить Heltec к WiFi: открой приложение Meshtastic → Module Config → WiFi → впиши SSID/пароль и перезагрузи плату. На OLED появится IP.
   - **Пауза между чанками** — пауза между частями длинного сообщения. 10 секунд — безопасный дефолт для LoRa, для загруженных сетей ставь 12–15.
   - Кнопка **Проверить связь** активно открывает соединение и показывает точную ошибку, если что-то не так.
4. **Расписание** — слоты с временем, часовым поясом, днями недели и набором полей. Изменения сохраняются автоматически. Под слотом — «следующий запуск».
5. **Отправить сейчас** — мгновенный ручной тест. Кнопка «Предпросмотр» строит сообщение без отправки.

### Вкладка «Чат»

Показывает последние ~200 текстовых сообщений mesh-сети, которые слышит твоя нода. Имя отправителя берётся из таблицы узлов Meshtastic. Можно отвечать прямо из UI — сообщение уйдёт broadcast'ом на канал, выбранный в настройках Heltec.

Под каждым входящим сообщением — RF-метаданные:

- **прыжки** — сколько ретрансляций прошёл пакет (0 = напрямую от отправителя)
- **RSSI** — сила последнего хопа в дБм, цветовая подсветка (зелёный ≥ −90, жёлтый −90…−110, красный ниже)
- **SNR** — соотношение сигнал/шум

Когда кто-то ставит реакцию через приложение Meshtastic (долгое нажатие → эмодзи), реакция появляется маленьким чипсом под исходным сообщением, а не отдельной строкой. Одинаковые реакции группируются со счётчиком.

Если ты на вкладке «Настройки» и пришло новое сообщение — на корешке вкладки «Чат» появится бейдж с количеством непрочитанных.

## REST API (если захочешь подёргать снаружи)

| Метод | Путь | Что делает |
|---|---|---|
| GET    | `/api/config` | Текущий конфиг |
| POST   | `/api/config` | Частичное обновление (location/mesh/message) |
| GET    | `/api/cities?q=...` | Поиск города |
| GET    | `/api/fields` | Список доступных полей |
| GET    | `/api/schedules` | Слоты |
| POST   | `/api/schedules` | Создать слот |
| PATCH  | `/api/schedules/<id>` | Изменить слот |
| DELETE | `/api/schedules/<id>` | Удалить |
| POST   | `/api/preview` | Сгенерировать текст без отправки |
| POST   | `/api/send` | Собрать и отправить сейчас |
| GET    | `/api/mesh/status` | Состояние подключения |
| POST   | `/api/mesh/connect` | Принудительно открыть соединение |
| GET    | `/api/chat/messages?since=<id>` | Новые сообщения из mesh |
| POST   | `/api/chat/send` | Отправить произвольный текст в mesh |
| GET    | `/api/scheduler/jobs` | Активные задания + время следующего запуска |

## Решение проблем

- **`Permission denied: '/dev/ttyUSB0'`** — пользователь не в группе `dialout`. Добавь и перезагрузись:
  `sudo usermod -aG dialout $USER && sudo reboot`
- **`Не найдено USB-устройство Heltec`** — проверь кабель (часто бывают «только зарядка»), `lsusb` и `dmesg | tail` после подключения. Heltec V4 обычно регистрируется как CP210x или CH9102.
- **`No route to host` через WiFi** — Heltec получил другой DHCP-адрес, либо в роутере включена client/AP-изоляция. Закрепи IP Heltec в DHCP-таблице роутера, чтобы это не повторялось.
- **`Data payload too big`** — бот теперь сам режет длинные сообщения, но если всё равно ловишь ошибку — убери одно поле из слота или сократи название города.
- **Расписание не сработало** — открой `/api/scheduler/jobs` в браузере, посмотри `next_run`. Скорее всего бот был оффлайн ровно в этот момент (дефолтный misfire grace 1 час покрывает короткие перезапуски).
- **Неверное время отправки** — проверь часовой пояс в слоте, потом `timedatectl` на Pi (часы должны быть синхронизированы).
